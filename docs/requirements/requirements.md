## 1. 概要

### 1.1 背景

本アプリは学習課題として作成する。作成を通して、Web アプリ開発（HTML / CSS / JavaScript）と、クラウドサービスを使ったデータ保存・ログインの基礎を習得する。
また、手元のメモや紙で管理しているタスクは、次の点で不便である。

- どのタスクがどこまで進んでいるか、一目でわからない
- 使う場所（自宅・学校など）によってパソコンが違うと、同じメモを見られない

### 1.2 目的

1. タスクを「未着手 → 作業中 → 完了」の流れで見える化する
2. どのパソコン・ブラウザからでも、同じタスクを見て編集できるようにする
3. ブラウザやパソコンに問題が起きても、データが失われないようにする

要件定義書は、本書と次の詳細文書でできている。本書には全体にかかわる内容と各詳細文書の概要を書き、詳しい内容は詳細文書に書く。同じ内容を 2 か所に書かない。

## 2. 範囲

### 2.1 対象範囲

開発は 2 回に分けて行う。各版の範囲は次のとおりで、版ごとに検収する。

| 版 | 含む機能（要件 ID） |
| --- | --- |
| 第 1 版 | ログイン・ログアウト（A-1〜A-6）、ボード表示（B-1〜B-5）、カードの追加・削除・リスト間の移動（C-1〜C-9）、保存・同期（D-1〜D-8）、手動バックアップと復元（K-1〜K-9） |

### 2.2 対象外（今回やらないこと）

| 項目 | 補足 |
| --- | --- |
| スマートフォン・タブレットへの対応 | 表示されても動作は保証しない |
| 複数人での 1 つのボードの共有 | 利用者ごとにボードは別々 |

## 5. 用語

| 用語 | 意味 |
| --- | --- |
| ボード | ログイン後に表示される画面全体。リストが横に並ぶ |
| リスト | 縦の列。「未着手」「作業中」「完了」など |
| カード | 1 つのタスク。リストの中に縦に並ぶ |
| 許可リスト | アプリを使ってよい Google アカウント（メールアドレス）の一覧。作成者がデータベース上で管理する |
| 同期 | ある画面で行った変更を、同じ利用者がほかのパソコン・ブラウザで開いている画面にも反映すること |
| エクスポート | すべてのリストとカードを 1 つのファイルにしてパソコンに保存すること |
| インポート | エクスポートしたファイルを読み込み、データをその時点の状態に戻すこと |
| 自動バックアップ | アプリがサーバー上に 1 日 1 回、自動でデータの控えを作ること |
| 確認ダイアログ | 操作を実行する前に「よろしいですか？」と確認する小さな画面 |
| トリム | 入力した文字の前後にある空白（半角・全角スペース、タブ、改行）を取り除くこと |
| 文字数 | Unicode の文字（コードポイント）の数。漢字・ひらがな・英数字は 1 文字。絵文字の一部（肌の色を変えたもの、国旗など）は、見た目は 1 文字でも 2 文字以上として数える |

## 6. 利用の流れ

1. ブラウザでアプリの URL を開く
2. 「Google でログイン」ボタンを押し、Google アカウントでログインする
3. ボードが表示される
4. やることができたら「未着手」にカードを追加する
5. 取りかかったらカードを「作業中」へ、終わったら「完了」へドラッグする
6. 週に 1 回程度、エクスポートでバックアップファイルをパソコンに保存する
7. 共用のパソコンで使った場合は、最後にログアウトする

## 11. 非機能要件

### 11.1 性能

次の条件で測定する：リスト 10 個・カード 500 枚、3.2 の対応環境、下り 10Mbps 以上の回線。

| ID | 内容 | 目標値 |
| --- | --- | --- |
| N-1 | ログインしてからボードが表示されるまで | 3 秒以内 |
| N-2 | 追加・削除・移動の操作をしてから、画面に反映されるまで | 0.5 秒以内 |
| N-3 | 操作をしてから、サーバーへの保存が終わるまで | 2 秒以内 |
| N-4 | ほかの画面への反映（D-3） | 5 秒以内 |
| N-5 | 「エクスポート」を押してからダウンロードが始まるまで | 3 秒以内 |

### 11.2 可用性・データ保全

| ID | 内容 |
| --- | --- |
| N-6 | 稼働時間は、使うクラウドサービスの稼働に従う。本アプリ独自の稼働率の目標は設けず、計画的な停止は行わない |
| N-7 | クラウドサービスの障害で使えない間は、D-4 または D-6 のメッセージを表示する。障害が直れば、操作なしで使える状態に戻る |
| N-8 | サーバー上のデータが失われた場合は、最新のエクスポートファイル（第 2 版では最新の自動バックアップも）から戻す。失われる可能性があるのは、最後のバックアップ以降の変更のみ |

### 11.3 セキュリティ

| ID | 内容 |
| --- | --- |
| N-9 | 通信はすべて HTTPS（暗号化）で行う |
| N-10 | ログインしていない状態では、データの読み書きを一切できない |
| N-11 | 各利用者は自分のデータだけを読み書きできる。これをアプリの画面側だけでなく、サーバー側（データベースの権限設定など）でも制限して守る |
| N-12 | 許可リストの判定もサーバー側で行う |
| N-13 | パスワードは本アプリでは扱わない（Google のログイン画面で入力する） |
| N-14 | 共用のパソコンで使ったあとはログアウトが必要であることを、操作マニュアルに書く |

### 11.4 使いやすさ

| ID | 内容 |
| --- | --- |
| N-15 | 画面の文字はすべて日本語とする |
| N-16 | 文字と背景の色の明るさの比（コントラスト比）を 4.5:1 以上とする |
| N-17 | データが失われる操作（削除・インポート・復元）の前には、必ず確認ダイアログを出す |
| N-18 | 押せるボタンにマウスを乗せたときは、マウスカーソルを指の形にする |

### 11.5 保守性

| ID | 内容 |
| --- | --- |
| N-19 | ソースコードは GitHub のリポジトリで管理する |
| N-20 | リポジトリの README に、開発環境の準備手順、データベースの作成手順、公開手順を書く |

## 12. リスクと対策

| No | リスク | 影響 | 対策 |
| --- | --- | --- | --- |
| R-1 | クラウドサービスの無料プランの上限を超える | その日の残り時間、保存・読み込みができない | 想定する利用量（1 日 数百回の操作）は上限より十分少ない。保守期間中は月に 1 回、使用量を確認する |
| R-2 | クラウドサービスの無料プランの内容が変わる・終了する | 費用が発生する、または使えなくなる | 変更の連絡があった時点で承認者に報告し、16 章の手続きで対応を決める |
| R-3 | 誤ってデータを削除する | データが失われる | 確認ダイアログ（N-17）とバックアップ（K-1〜K-14）で戻せるようにする |
| R-4 | Google アカウントにログインできなくなる | アプリを使えなくなる | Google アカウント側の問題のため、本アプリでは対応しない。エクスポートファイルは手元に残る |
| R-5 | ブラウザの仕様変更で動きが変わる | 一部の機能が動かなくなる | 保守期間中は不具合として対応する（15 章） |

### 13.3 不具合の重さと扱い

| ランク | 内容 | 例 | 扱い |
| --- | --- | --- | --- |
| A | データが失われる・壊れる、または主な機能が使えない | 追加したカードが消える、ログインできない | 修正して再テストするまで合格としない |

### 15.2 保守で行うこと

| 内容 | 期限 |

- 利用者が誤って削除したデータの復元作業（利用者がバックアップから戻す）

## 16. 変更管理

承認後に要件を変える場合は、次の手順で行う。

| 手順 | 内容 | 担当 |
| --- | --- | --- |
| 1 | 変更したい内容と理由を、GitHub の Issue に「変更依頼」として書く | 依頼する人（どちらでもよい） |
| 2 | 変更による影響（作業時間、納期、ほかの機能への影響）を調べ、Issue に書く | 作成者 |
| 3 | 変更するかどうかを決める | 承認者 |
| 4 | 変更する場合は本書または詳細文書（1.3）を書き直し、版数を上げて改訂履歴に記録し、再度承認を受ける | 作成者・承認者 |

版数の上げ方：文言の修正のみは 0.1 上げる（例：1.0 → 1.1）。機能の追加・削除は 1.0 上げる（例：1.1 → 2.0）。

詳細文書を変えた場合は、その文書の版数を上げて改訂履歴に記録する。あわせて本書の版数も上げ、改訂履歴に「どの詳細文書を何版にしたか」を記録する。承認は本書で行うため、本書の版数が要件定義書全体の版数となる。
