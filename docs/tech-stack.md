## 1. 本書の目的

使う製品・サービス・開発ツールを決め、その理由を記録する。要件定義書の次の項目に対応する。

| 要件定義書 | 内容 |
| --- | --- |
| P-1 | データを保存する RDB の製品・サービスを決める |
| P-2 | 無料プランの上限値を公式サイトで確認し、記録する |
| U-3 | 上の 2 つを技術選定時に決める |

選定の結果によって変わる設計（物理設計・運用設計）は、選定の後に基本設計書 2 章で行う。

---

## 2. 選定の条件

要件定義書と基本設計書から、使う製品・サービスには次のことが求められる。

| No | 確認すること | 理由 |
| --- | --- | --- |
| 1 | RDB である | P-1 |
| 2 | Google アカウントでログインできる | A-1 |
| 3 | 行ごとのアクセス制御ができる、またはサーバー側の処理で同じことを実現できる | BR-8 |
| 4 | 複数の変更をまとめて行う仕組み（トランザクション）がある | BR-6 |
| 5 | ほかの画面での変更を 5 秒以内に受け取れる | D-3 |
| 6 | 無料プランで、容量 70MB 以上（[データ設計書](design/data-design.md) 9）・利用者 5 人分が使える | P-2 |
| 7 | JSON 型を扱える、または文字列として保存できる | データ設計書 4.6 |

あわせて、次の前提も満たす。

| 前提 | 根拠 |
| --- | --- |
| 画面は HTML / CSS / JavaScript で作る | 要件定義書 1.1（学習の目的） |
| HTTPS で公開でき、URL を開くだけで使える | P-3、N-9 |
| ソースコードは GitHub で管理する | N-19 |
| 費用は 0 円 | P-2 |
